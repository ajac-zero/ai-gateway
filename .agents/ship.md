Ship this thread's changes as a fork series by following the `maintaining-forks-with-jj-fork` skill. This repository is a fork: `fork/main` is generated from upstream `main` plus every `patch/*` and `tooling/*` series and every `glue/*` integration merge, so never commit onto `fork/main` or `main`.

1. Inspect `jj status` and the fork graph. Decide where the changes belong: upstreamable gateway changes in `patch/*`, fork tooling (`.agents/`, `.jj-fork.toml`, `AGENTS.md`, skills) in `tooling/*`. Extend an existing series with `jj new <series>`. For independent work, preserve this thread's edits in their own described jj change, then run `jj fork create patch/<short-name> -m 'Describe the change'` (or `tooling/*`) from a clean working copy and move only those edits into the created change. Never use `jj patch-new`, and never discard edits to satisfy create. If ownership is unclear or spans series, stop and ask.
2. Keep the series rooted on upstream alone, with no other series' code. Before assembling, verify that series alone in an isolated checkout of its tip: every commit conflict-free, `go build ./...`, `go vet` and `go test -count=1` for the packages it touches, and `make apigen apidoc` with no unintended diff after `api/` edits. Fix failures in the series, then move its bookmark to the new tip. jj-fork does not run this on edit.
3. Run `jj new fork/main`, then `jj fork assemble --save-plan /tmp/ship-plan.json --report /tmp/ship-report.json`. It restacks glues and checks the fork without publishing. Keep plans outside the working tree. Use assemble, not sync: Ship must not rebase unrelated series onto a new upstream.
4. If the plan needs repairs, use `jj fork repair start` for its issue ids and follow the skill. Resolve integration failures in named glues, never in a series or `fork/main`. Submit tasks in this clone with `jj fork repair submit <dirs> --save-plan /tmp/ship-ready.json`. For a stale source or remote, prepare a new plan.
5. Apply the ready plan with `jj fork apply /tmp/ship-plan.json --push` (or the successor plan). Ship authorizes this publication. Do not move or push PR-head bookmarks unless asked. Inspect the report before retrying any partial push failure.
6. Report the series and tip, glues changed, published `fork/main`, checks and ignored upstream failures, and any incomplete publication. Archive only after successful delivery.
