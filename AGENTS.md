# Fork conventions

This checkout is a fork of [envoyproxy/ai-gateway](https://github.com/envoyproxy/ai-gateway). `fork/main` is generated: it merges upstream `main` with every `patch/*` and `tooling/*` series and every `glue/*` integration merge. Orbs and Ship start from `fork/main`. Every change ends up in one of those series. The engine is jj-fork; `.jj-fork.toml` holds its checks.

- Load the `maintaining-forks-with-jj-fork` skill (`jj fork skill maintaining-forks-with-jj-fork`) before any version-control work: committing, creating or moving bookmarks, rebasing, pushing, or shipping. Use `jj`, not Git, to change history. Never commit onto `fork/main` or `main`.
- Plain feature work needs no setup. Edit the working copy and verify as usual. The Ship button turns the result into a series (`.agents/ship.md`).
- A new feature becomes its own `patch/<name>`, created with `jj fork create`, rooted on upstream `main`. It must build and pass its tests on upstream alone, so do not depend on code that only another patch adds. The working copy includes every patch, so check before reusing a helper, type, or file: `git grep -n <name> upstream/main` shows whether it exists upstream, and `jj log -r 'fork_patches()'` lists the patches. If the feature extends an existing patch, say so; it then belongs in that patch's series.
- Verify the series alone before assembling: `go build ./...`, then `go vet` and `go test -count=1` for the packages it touches. Regenerate with `make apigen apidoc` after `api/` changes. jj-fork does not run this per series on edit.
- Fork checks skip `tests/controller`, `tests/crdcel`, `/tests/e2e` and `tests/data-plane`, which need a cluster or Envoy. Set `FORK_UPDATE_TEST_EXCLUDE` to override. Failures that also fail on bare upstream are reported as ignored; do not fix them in a patch. A full check takes about 15 to 30 minutes and 3 GB.
- Fork-only tooling (`.agents/`, `.jj-fork.toml`, `AGENTS.md`, the bundled skills) belongs in `tooling/agent-workflow`, not in a patch. After upgrading jj-fork, rerun `jj fork skill --install` there.
- The scheduled fork owner runs `jj fork sync --save-plan`; fixers repair isolated tasks and never push. Fixer orbs are separate machines, so they must return their repair tasks to the owner.
